# OKAWARI 門頭屏 · 後台

## 怎麼開

雙擊 `後台.bat`。它會印出網址。

```
瀏覽器（介面）──▶ 這個後台 ──網路線──▶ 控制卡 ──▶ LED 屏
```

後台是中間人：只有它同時看得到卡和外面。現在由筆電扮演，
上線之後換成門市的小主機，跑的是同一套程式。

## 介面在哪

**介面已經不在 `server.py` 裡面了**，搬到 `../docs/index.html`。
同一份檔案，三個地方開得起來：

| 從哪開 | 網址 | 用在什麼時候 |
|---|---|---|
| 這台電腦 | `http://localhost:8080` | 平常 |
| 同一個 Wi-Fi 的手機 | `http://<筆電IP>:8080` | 現場調畫面時跑來跑去 |
| GitHub Pages | `https://<帳號>.github.io/<repo>/` | 遠端。開了之後在「連線設定」填後台網址 |

改介面就是改 `docs/index.html`，然後跑 `../推上GitHub.bat`。

> **注意 https 打 http 的限制。** GitHub Pages 是 https，瀏覽器只准它打
> `localhost`，打 `192.168.x.x` 會被擋掉（混合內容）。
> 要從外面連門市，後台得有一個 https 網址 —— 用 Cloudflare Tunnel，
> 做法在 `../遠端架構.md`。

## 這台電腦要裝什麼

換一台電腦跑，只需要這三樣，十分鐘可以裝好：

| 東西 | 怎麼裝 | 用途 |
|---|---|---|
| Python 3 | python.org | 全部程式 |
| Pillow | `pip install pillow` | 畫面運算 |
| ffmpeg | `winget install Gyan.FFmpeg` | 把畫面編成卡吃的影片 |

## 檔案在哪

| 檔案 | 是什麼 |
|---|---|
| `stores.json` | 門店登錄檔。畫布尺寸、卡的資料、每店播哪些內容、調校參數 |
| `stores.範本.json` | 上面那個的乾淨版本。**進 git 的是這個**，實際資料不進 git |
| `artwork.py` | 美術層。勇者、壞人、石頭、漸變，移植自 `OKAWARI 門頭屏模擬器 v1.0.html` |
| `compiler.py` | 編譯器。按各店畫布算出畫面 → 編成影片 → 送檔 → 建節目 |
| `server.py` | 後台。API、排程、卡的連線 |
| `../docs/index.html` | 介面 |
| `build/` | 編出來的影片，可以直接用播放器打開檢查 |

`stores.json` 每次存檔會自動留一份 `.bak`。

換一台機器：把資料夾拉下來，`stores.範本.json` 複製成 `stores.json`，
再填上那張卡的 `device_id`。

## 卡主動回連（遠端控制的關鍵）

門市在 4G 後面的話，我們是連不進去的，只能等卡自己撥出來。
要開這個功能，啟動前設一個環境變數：

```
set OKAWARI_HQ_PORT=6000
後台.bat
```

後台就會在 6000 埠等卡撥回來，撥回來的線會蓋過掃網段那條。
把卡指向這台機器：對 `/api/hq` 送 `{"host": "...", "port": 6000}`。

**這條路還沒有在實體卡上驗證過。** 驗證步驟寫在 `../遠端架構.md` 的「測試一」，
上線前一定要先做完。

## 現場連不上卡的時候

跑 `../_明天帶去_LED實測_20260810/02_程式端/現場連線.bat`。

它會自己判斷狀況：掃描找卡 → 找不到就聽卡有沒有在喊 DHCP →
有的話筆電自己當一台 DHCP 伺服器發 IP 給它。

最後的救援路徑是卡自己的 Wi-Fi 熱點。密碼出廠是 `88888888`，
**上線前一定要改掉** —— 門口的螢幕不能讓路過的人連得上。

## 已知的坑（都是 2026-08-10 實測踩出來的）

- **卡是用 md5 認檔案的，不是檔名。** 送一個內容重複但檔名不同的檔，
  卡會說「已存在」卻不建立那個檔名，之後節目引用就找不到。
- **`AddProgram` 之後不能馬上 `SwitchProgram`**，要重試到 `kSuccess`。
  中間會回 `kInvalidXmlIndex`，那不是 guid 錯，是卡還在重建節目單。
- **卡上的媒體檔要定期清**，堆太多會讓 `AddProgram` 一直回 `kDownloadFileFailed`。
  發佈流程已經會自動清。
- **`SetLuminancePloy` 四個子節點要送齊**（mode / default / ploy / sensor），
  少送任何一個都回 `kParseXmlFailed`。
- **卡不播動畫 GIF**，只顯示第一幀。
- **圖片序列當動畫只跑得動約 6 fps**，而且會出現一條垂直線掃過去。
  所以動畫一律走影片。
- **影片截不到圖。** `GetScreenshot2` 對影片內容回傳全黑，因為影片畫在硬體疊加層。
  總部要遠端巡檢的話不能只靠截圖 —— 要看的是後台的 `/api/health`。
